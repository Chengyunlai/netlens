# 学习地图：这个项目能教什么，教不到什么

除"诊断工具"之外，这个项目还有第二个用途：**作为网络与操作系统知识的学习载体**。
这份文档记录这个载体的**能力边界**——哪些知识在这里能学到、通过哪一步学到；
哪些在当前定位下学不到、需要另找载体。项目定位变化时同步更新本文件。

最后更新：2026-09-29（初稿，未提交）

## 结论

以"覆盖工作中大部分场景的网络与操作系统知识"为标准，当前路线图
（probe → page → compare）覆盖的是**HTTP 客户端视角下的传输层**，约为目标的三分之一。

余下的缺口分两类，处理方式完全不同：

| 类别 | 内容 | 处理方式 |
| --- | --- | --- |
| 路线图往后走自然覆盖 | 多 Origin 并发、HTTP/2 多路复用、ALPN 真实协商、TLS 会话恢复 | 按计划推进，不必改定位 |
| 被项目自身约束挡住 | 原始 IO 多路复用、UDP / QUIC、内核队列与 socket 选项 | 要么扩边界，要么换载体 |

## 约束在"学习"上的代价

三条既定约束在"零安装运行"上是优点，但会挡住一部分知识：

| 约束 | 换来的 | 挡掉的 |
| --- | --- | --- |
| 运行时零第三方依赖、只用内置模块 | 任何机器零安装可跑 | socket 生命周期、fd、读写缓冲被运行时封装，只看得见事件回调，摸不到 IO 多路复用 |
| 不自己实现 HTTP/3 客户端 | 不重复造轮子 | 整条 UDP 线 |
| 当前只做单请求串行探测 | 度量口径先钉死 | 并发、事件循环压力、连接池上限 |

## 能学到的部分

### 已落地（probe 阶段）

| 知识点 | 在本项目里的落点 |
| --- | --- |
| DNS 解析 | 解析完成的时间戳。解析默认由 libuv 线程池执行（`getaddrinfo` 是阻塞调用）——理解"事件循环遇到阻塞系统调用"的真实案例，也是"默认只有 4 个解析并发"的源头 |
| TCP 握手与 RTT | 连接建立时间戳 ≈ 1 个 RTT，是所有延迟优化的基数 |
| TLS 握手 | 协商到的版本与 ALPN 结果；TLS 1.3 = 1 RTT，1.2 = 2 RTT |
| 失败分层 | 同一句"请求失败"拆成 DNS / TCP / TLS / HTTP 四种，对应四个不同排查方向 |
| 超时与内核重试 | 目标端口只丢 SYN（不回 RST）时内核会重试到约 75 秒，应用层必须自己兜底，不能依赖 socket 空闲超时 |

### 路线图内可补

| 知识点 | 补在哪一步 |
| --- | --- |
| 并发与连接上限 | page 阶段的多 Origin 采集 |
| HTTP/1.1 队头阻塞 vs HTTP/2 多路复用 | 协议协商探测 + page |
| 证书链、SNI、会话恢复、0-RTT | 协议协商探测 |

| 知识点 | 建议载体 |
| --- | --- |

| 半包 / 粘包、报文边界判定 | 同上 |

## 已落地：原始实现（`examples/raw-network/`）

这里原先写的是"建议加一个裸 socket 模式"。已经做了：在 `examples/raw-network/` 下
从零实现了四层，走的是学习层路线（两条路线的分工见
[AGENTS.md](../AGENTS.md#两条实现路线)）。

它为什么不放在 `src/`：产品主线允许用 `http` / `https`，学习层只允许用 `net` / `tls` / `dgram`。
同一个协议边界，产品线交给成熟实现处理，学习层必须自己处理 —— 那正是要看的东西本身。

实测能看见的东西：

- **DNS**：报文长度、名字压缩指针、CNAME 链、TTL；UDP 没有握手也没有重传
- **TCP**：内核文件描述符、客户端端口由内核分配、握手 ≈ 1 RTT、`TCP_NODELAY`
- **TLS**：SNI 是明文发出的、ALPN 协商结果、证书链与根证书、1 RTT 与 2 RTT 的差异
- **HTTP**：一次 `data` 回调拿到多少字节由内核缓冲区决定（实测 19 万字节的响应被切成
  12 次 16384 字节，而另一个站点是一次读完 4268 字节）；头与正文可能同批到达；三种结束规则
- **失败**：DNS / TCP / TLS / HTTP 分层报错，而不是一句"请求失败"

逐层导读与实测数据见[它的 README](../examples/raw-network/README.md)。

## 学习顺序建议

1. **已完成** —— 跑通产品线的 probe，看清五段耗时各自来自哪个事件
2. **已完成** —— 原始实现：从"用别人写的客户端"走到"自己写一次客户端"
3. 未做 —— 并发与连接复用：多 Origin、连接池上限、HTTP/2 多路复用（[issue #3](https://github.com/Chengyunlai/netlens/issues/3)）
4. 未做 —— 协议协商探测：TLS 会话恢复、0-RTT、证书链的完整验证过程（[issue #4](https://github.com/Chengyunlai/netlens/issues/4)）
5. 未做 —— 离开本项目做独立实验：UDP / QUIC、抓包、容器网络、内核队列（不属本仓库范围，不建 issue）
